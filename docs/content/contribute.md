# Help fill the gaps

The dataset improves as people with sources add to it. If you know the result of an election, where it took place, or what the employer made, you can send it in. Accepted changes are credited and appear in the version history.

<div data-component="gap-tiles"></div>

## What helps most

- **Election results.** The outcome or vote count of an election the Board ordered. Good sources are the Board's certifications and supplemental decisions, NLRB annual reports, and local or union newspapers that reported the vote.
- **Locations.** The town of the plant where the election took place. Company histories, city directories, and newspaper reports work well.
- **Industries.** What the employer made or did at that plant.

Every suggestion needs a source that someone else can check: a citation, an archive reference, or a link.

## Three ways to send a correction

1. **One at a time.** Use the form below.
2. **Many at once.** Fill in the [corrections template](data/templates/corrections_template.csv), one row per change, and send it with a GitHub issue or by email.
3. **Through GitHub.** Open a pull request that adds rows to a file in the `corrections` folder of the repository. CONTRIBUTING.md in the repository explains the format.

## What happens next

<ol class="steps">
<li><span>A project member checks the source and the proposed value.</span></li>
<li><span>Accepted changes are recorded in the <code>corrections</code> folder with the source, and with your name if you want credit.</span></li>
<li><span>The next release applies them. Its entry on the <a href="#versions">Versions</a> page lists each change, with the old and new values.</span></li>
<li><span>Earlier releases stay available, so published work that used them can still be checked.</span></li>
</ol>
